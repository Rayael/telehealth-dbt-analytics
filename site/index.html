Telehealth analytics with dbt

A small data platform to practice what an analytics team does every day: load messy files, clean them in layers, test the result, and serve a star schema to Power BI. It runs on dbt and DuckDB.

See the charts Browse the dbt docs

About the numbers. Every row comes from a generator with a fixed seed, with data problems added on purpose. The charts show that the pipeline works. They say nothing about real patients or a real service.

Pipeline

Three raw files (patients, doctors, consultations) are loaded as text. Each layer then does one job, so a problem can be traced to the step that caused it.

Row counts come from the warehouse built by the last run. Views have no stored rows of their own, the count is what they return.

Data model

The gold layer is a Kimball star schema. The grain of the fact table is one row per valid consultation. Each dimension has its own surrogate key, built as a hash of the business key so it stays the same between runs.

Unknown member
Each dimension has a row with key -1. A consultation that points to a patient we never received is kept and linked to it, so no row is lost and no join breaks.
Quarantine, not delete
Consultations that fail a rule go to dq_rejected_consultations with the reason. Nothing disappears without a trace.
Marts
mart_daily_service_kpis and mart_doctor_monthly are pre-aggregated versions of the fact table for reporting. The Power BI notes list the relationships and DAX measures.

Data quality

The generator adds problems that real source files have. Silver deals with each one, and a reconciliation model checks that every delivered row is accounted for.

    Tests and CI

      Generic tests
      unique, not_null and accepted_values on keys and categories, and a relationships test from the fact table to each of the five dimensions.
      Custom tests
      non_negative and value_between, written once as generic tests and reused on durations, waits, scores and rates.
      Singular tests
      Two SQL files: no valid row may be lost between silver and gold, and no consultation may end before it starts.
      Unit tests
      The cleaning logic is run on small hand-written inputs, for example a duplicated patient, a date written as 15.03.1985 and a consultation that ends before it starts.
      One warning on purpose
      The source test on duplicate consultation ids is set to warn. The duplicates are in the raw data by design, and silver removes them.
      CI
      On every push to main, GitHub Actions generates the data, runs dbt build and dbt docs generate, and publishes this site together with the docs.

      Run it

      You need Python 3.10 or newer. Nothing else is installed on your machine, the warehouse is one DuckDB file.

      git clone https://github.com/YOUR_USER/telehealth-dbt-analytics.git
cd telehealth-dbt-analytics
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

make site      # data, dbt build, site data, dbt docs
make serve     # http://localhost:8000

      To get CSV and Parquet files of the gold tables for Power BI, run make export.
